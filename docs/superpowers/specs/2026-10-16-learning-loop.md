# Evidence-linked learning loop

The user authorized implementing the improvements identified in the ChatGPT/Gemini comparison. This pass delivers reliable assistance records, evidence-linked objectives and review, guided next actions, technical activity formats, source-file import, and repeatable evaluation. Existing explicit consent and source policy remain binding.

## Contract

Keep API/schema version 1 additive and existing stores readable without read-time mutations. New frontend capability checks must avoid implying support from older backends. Do not install or restart the daily Hermes profile. Use existing React/Python/SQLite, no new runtime dependencies.

- `start` and `brief` optionally accept `learner_profile` `{background: string, goal: string, minutes: integer 1..240}`. Omitted fields retain values, and an empty profile is valid. Background/goal are at most 2000 characters.
- Track `objectives` remains strings for legacy clients. Track responses also expose `objective_details: [{id,title}]`, with deterministic stable IDs for unchanged titles across reordering and legacy stores. Editing a title creates a different identity; historical activity objective snapshots retain the old wording.
- Activities optionally accept `objective_ids: string[]`, `competency: conceptual|practical|both` (default conceptual), `purpose: diagnostic|practice|transfer` (default practice). Validate IDs against the current track and preserve them on revision when omitted. Safe activity responses expose those fields and `objective_snapshots`.
- `help` optionally accepts `content` (nonempty <=5000 characters) and `request_id` (nonempty <=100 characters). Supplying generated content requires a request ID. The same run/request ID plus identical level/content/channel is idempotent; conflicting retries reject. Store actual content, `author_kind` and `origin` (`authored`/`generated`) on the event. Existing authored help still works. Never leak help content through snapshots or attempts whose sources are restricted to metadata-only on the model channel; preserve counts/levels. Generated help does not silently unlock a canonical full solution. Prior help exposure follows immutable activity lineage.
- `assess` optionally accepts `criterion_results: [{index: integer, outcome: needs-work|developing|demonstrated, feedback: string}]` and `uncertainty: string` (<=2000). When supplied, require exactly one entry per immutable criterion; overall outcome must match the weakest criterion result. Preserve method attribution, supersession and disputes.
- State/track snapshots include `objective_progress` rows `{track_id,objective_id,title,status,attempt_count,assessment_count,assisted_attempt_count,latest_assessment,conceptual,practical}`. Status is `not-started|awaiting-assessment|needs-work|developing|demonstrated|disputed`. Conceptual/practical are summaries `{status,attempt_count,assessment_count}`. Summaries exclude superseded judgments, flag unresolved disputes, expose method and uncertainty, and never call a percentage mastery. Evidence counts are derived; reads create no records.
- State/track snapshots include `next_actions` rows `{track_id,kind,title,reason,activity_id?,objective_id?,attempt_id?}`. One prioritized action per track. Kinds: `proposal`, `assessment`, `dispute`, `review`, `practice`, `author`, `resume`. Prefer unfinished proposals, unresolved disputes, pending assessments, due reviews, unattempted latest activity versions, then a new transfer activity. Archived/paused tracks request explicit resume. Recommendations never enroll or write. `resume_brief` uses this same projection.
- Assessment creates one review per objective when linked (policy_version 2), with `objective_id`, retaining `activity_id` as the triggering evidence. Unlinked legacy activities keep policy 1. Outcome intervals remain transparent 1/3/7-day heuristics, based on effective objective evidence and its timestamp rather than whichever assessment was saved last. Weaker competencies and conflicting self/agent judgments remain due; unrelated feedback cannot erase pending answers/disputes. Manual dates survive feedback/corrections on existing tasks; assessment of new attempted work resumes automatic scheduling. Review suggests an unattempted alternative activity with the same objective when possible. Superseded/retired activity versions or revisions moved to another objective must not be suggested as new practice. With no matching current activity, request a new objective-specific review task. Self and agent feedback are labeled explicitly.
- Add schema-1 structured visual types `state-machine` (`states:[{id,label}], initial:string, steps:[{from,to,label,explanation}], visible_steps`) and `code-trace` (`code:string <=12000, language:string <=40, steps:[{line:integer>=1, label,explanation,variables:[{name,value}]}], visible_steps`). Both support title. Bounded validation: 1..20 states, 1..30 steps, <=20 variables per step. Reuse sequence label/explanation bounds. Verify step continuity, references, and code line range. Gate future steps consistently; render plain strings without execution.
- Add `capabilities` list in state responses: `objective-evidence-v1`, `generated-help-v1`, `structured-visuals-v1`.

## Learner experience

Track setup offers optional background, intended outcome, available session minutes. Track workspace adds Progress showing objective evidence and a prominent next action. Actions navigate to the relevant activity, pending evidence or a specific tutor request. For required model work, use a verified native host handoff if feasible; otherwise make the existing copyable prompt precise, with track/activity/attempt context and honest instructions. Do not introduce an unconfigured inference service.

Activity authoring exposes objective links, purpose, competency and optional structured visual JSON with useful examples and validation errors. Practice labels match explanation/prediction/trace/build, includes criterion-level self assessment after submission, displays uncertainty and actual assistance history safely, and makes review/next activity accessible.

Source import reads user-selected UTF-8 text/Markdown/code files locally, up to 200 KB and 50000 characters. Validate supported extensions, encoding, NUL and limits; show editable excerpt and filename locator before the explicit Add source action. Never auto-attach, fetch links, execute code or read additional paths.

## Validation

Regression tests cover legacy reads/no mutations, objective identity and cross-track rejection, help idempotency and privacy, assessment criteria/corrections/disputes, objective review and recommendations, schema gating/malformed visuals, source-file parsing, and useful UI state transitions. Browser proof covers creation → objectives → activity → help → exact answer → assessment → progress → next action, imports, all visual types, reload, dark and mobile. Build both host bundles and package all new runtime files.

Add an evaluation harness with realistic cases and an explicit distinction between deterministic tool-flow results and live-model/teaching review. Actual provider runs require available configured host access; report them separately rather than treating scripted fixtures as proof of teaching quality.
